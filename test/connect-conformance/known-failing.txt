# Test cases of `just connect-conformance` that are expected to fail.
# connectconformance runs them and requires them to fail, so an entry
# that starts passing breaks the run until it is removed here.
#
# Every group says why. None of them is a defect of pb's Connect or gRPC
# code: they are the limits of the buffered HTTP handler contract
# (phase 2 of the Connect work) and defects of tarantool-http2.

# --- Connect full-duplex bidi streams -----------------------------------
# tarantool-http2 hands a request to the HTTP handler only once its body
# has ended (END_STREAM), and a full-duplex client waits for the first
# response before it sends its next message and ends the request: the
# call never reaches pb.connect and the client times out. Needs a
# streaming HTTP handler API in tarantool-http2 (phase 2). gRPC
# full-duplex calls do not go through the HTTP handler and pass.
# (Timeouts/.../bidi-stream/full-duplex, which has no further name
# component, passes anyway: it expects deadline_exceeded, and the
# client's own deadline produces it without the server seeing the call.)
**/Protocol:PROTOCOL_CONNECT/**/bidi-stream/full-duplex/*
# The Connect-only suites carry no Protocol component in their names.
Connect to HTTP Code Mapping/**/bidi-stream/full-duplex/*
